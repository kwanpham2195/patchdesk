# Same-revision GitHub reconciliation and compact merge command

## Summary

Patchdesk automatically reconciles bounded GitHub state only when it proves the open PR still matches the represented revision. Explicit **Refresh** alone adopts changed code/worktree state. Pending-review adoption is authoritative, never a draft merge. Merge becomes a compact method selector plus explicit **Merge** button; no dialog.

Plan: [`../../PLANS/2026-08-12-pr-metadata-reconciliation-and-workbench-polish.md`](../../PLANS/2026-08-12-pr-metadata-reconciliation-and-workbench-polish.md). ADR: [`../../../docs/adr/0017-separate-pr-reconciliation-from-revision-refresh-and-merge-confirmation.md`](../../../docs/adr/0017-separate-pr-reconciliation-from-revision-refresh-and-merge-confirmation.md).

## Context / Current State

`ReviewRefreshService.detect()` turns any observed remote difference into `updates_available`. `PendingReviewService.reconcile()` imports confirmed state but keeps locked state. Merge accepts `acknowledgedWarnings: boolean`, so a new warning set can be merged with an acknowledgement for older warnings. Finish-review summary state is dialog-local and can disappear when pending-review projection disappears.

## Goals

- Quietly reconcile same-revision PR metadata, Conversation, and authoritative pending draft.
- Protect all writes when revision identity cannot be proven current.
- Preserve typed Finish-review text across quiet draft replacement/removal.
- Use exact warning/revision acknowledgement before one-click Merge.
- Inherit the app theme in Pierre.

## Non-Goals

- Automatic code/worktree/Insight adoption, draft merging, write retry, new recovery controls, live GitHub writes during testing, or a tree-specific theme preference.

## Invariants

```ts
type RepresentedRevisionIdentity = {
  readonly headSha: GitSha;
  readonly baseSha: GitSha;
  readonly patchHash: ContentHash;
};

type Observation =
  | { readonly _tag: "Unchanged"; readonly detectedAt: IsoTimestamp }
  | { readonly _tag: "Reconciled"; readonly projection: ReviewWorkbenchProjection }
  | { readonly _tag: "RevisionChanged"; readonly detectedAt: IsoTimestamp }
  | { readonly _tag: "Unavailable"; readonly detectedAt: IsoTimestamp }
  | { readonly _tag: "Terminal"; readonly status: "merged" | "closed"; readonly detectedAt: IsoTimestamp };
```

- `Reconciled` requires matching head, base, and patch identity before and after remote reads. It cannot change session/worktree/revision artifacts.
- `RevisionChanged` exposes Refresh and revokes writes. `Unavailable` hides Refresh but blocks writes until a same-revision check succeeds.
- `Terminal` is the sole revision-precedence exception: terminal status applies, changed revision content does not.
- Pending-review adoption is forbidden while `WriteInFlight` or `OutcomeUnknown`.
- A Finding is actionable after a replaced draft only with evidence that no pending or published receipt exists.

## Alternatives Considered

### Option 1: Keep Refresh for all remote changes

Simple but stale after confirmed Patchdesk writes; rejected.

### Option 2: Renderer reads/adopts GitHub state

Breaks the main-process boundary and duplicates lifecycle rules; rejected.

### Option 3: Observation coordinator with specialized owners

`ReviewObservationService` coordinates revision proof and projection. `PendingReviewService` owns draft/receipt transitions; merge services own final write validation. Recommended for reuse and invariant locality.

## Recommendation

Add `ReviewObservationService`; retain `ReviewRefreshService.refresh()` for explicit revision adoption. The loopback API serializes a closed observation DTO. The renderer schedules/coalesces observations but never interprets raw GitHub state.

## Proposed Design

### Domain Model and Types

```ts
export type PendingReviewRevision = Brand<string, "PendingReviewRevision">;

export type FindingReviewReceiptState =
  | { readonly _tag: "Pending"; readonly reviewId: GitHubReviewNodeId }
  | { readonly _tag: "Published"; readonly reviewId: GitHubReviewNodeId }
  | { readonly _tag: "Historical"; readonly reason: "draft_replaced" | "draft_absent" | "evidence_incomplete" };

export type MergeWarningAcknowledgement = {
  readonly revision: RepresentedRevisionIdentity;
  readonly warningCodes: ReadonlyArray<MergeWarningCode>;
};

export type MergeCommandResult =
  | { readonly _tag: "Merged"; readonly projection: ReviewWorkbenchProjection }
  | { readonly _tag: "ReadinessChanged"; readonly readiness: MergeReadiness; readonly reasons: ReadonlyArray<MergeDisplayReason> }
  | { readonly _tag: "RevisionChanged" }
  | { readonly _tag: "Unavailable" }
  | { readonly _tag: "OutcomeUnknown" };

export type PendingReviewAdoption =
  | { readonly _tag: "Adopted"; readonly state: PendingReviewState; readonly revision: PendingReviewRevision }
  | { readonly _tag: "Locked"; readonly state: Extract<PendingReviewState, { readonly _tag: "WriteInFlight" | "OutcomeUnknown" }> }
  | { readonly _tag: "Unavailable" };
```

### Types, Interfaces, and APIs

```ts
class ReviewObservationService {
  observe(input: {
    readonly profileId: WorkspaceProfileId;
    readonly reviewId: ReviewId;
  }): Promise<Result<Observation, ReviewObservationFailure>>;
}

class PendingReviewService {
  adoptObservedState(input: {
    readonly profileId: WorkspaceProfileId;
    readonly reviewId: ReviewId;
    readonly observed: ViewerPendingReview | undefined;
    readonly publishedFeedback: GitHubPublishedFeedback | undefined;
  }): Promise<Result<PendingReviewAdoption, PendingReviewServiceFailure>>;

  submit(input: SubmitPendingReviewInput & {
    readonly expectedPendingReviewRevision: PendingReviewRevision;
  }): Promise<Result<PendingReviewCommandResult | { readonly _tag: "pending_review_changed" }, PendingReviewServiceFailure>>;
}

class MergeWriteController {
  merge(input: {
    readonly expectedRevision: RepresentedRevisionIdentity;
    readonly method: MergeMethod;
    readonly acknowledgement?: MergeWarningAcknowledgement;
  }): Promise<MergeCommandResult>;
}
```

```ts
type ObserveReviewResponse =
  | { readonly kind: "unchanged"; readonly detectedAt: string }
  | { readonly kind: "reconciled"; readonly workbench: WorkbenchResponse }
  | { readonly kind: "revision_changed"; readonly detectedAt: string }
  | { readonly kind: "unavailable"; readonly detectedAt: string }
  | { readonly kind: "terminal"; readonly status: "merged" | "closed"; readonly detectedAt: string };
```

The main process parses GitHub input and owns identity comparison. Renderer contracts carry opaque IDs/revisions and bounded projections only—never raw draft body, GitHub error, worktree path, or provider payload.

### Seams, Boundaries, Adapters, and Implementations

- **`ReviewObservationService`**: review lock; first/second PR identity read; bounded metadata/Conversation readers; terminal outcome; remote snapshot persistence; standard projection.
- **`PendingReviewService`**: only owner of pending-draft adoption, locked recovery, receipt classification, and submit revision check.
- **GitHub adapters**: return parsed head/base/patch identity, pending draft, published feedback, checks, conversation, and merge policy.
- **`ReviewWriteGate`**: rejects writes for `updates_available` and `unavailable`.
- **`MergeWriteController`**: final current-state read, acknowledgement comparison, exactly one GitHub merge call, typed result.
- **Renderer flow**: one in-flight/coalesced observation for visible workbench; stable Finish-review controller stores typed summary and open draft revision; compact merge component owns only UI state.

## Call Stacks and Data Flow

### Same-revision observation

```txt
visible workbench / confirmed write
  -> ReviewWorkbenchFlow.scheduleObservation()
  -> POST /v1/reviews/detect-updates
  -> parse protected request
  -> ReviewObservationService.observe()
  -> first PR identity read
  -> terminal? => Terminal (no revision adoption)
  -> identity differs => RevisionChanged
  -> identity unprovable => Unavailable
  -> bounded metadata + pending draft + published-feedback reads
  -> second identity read
  -> identity still matches
  -> PendingReviewService.adoptObservedState()
  -> save same-revision snapshot and session draft transition
  -> standard projection
  -> Reconciled DTO
  -> renderer identity guard
  -> replace bounded projection / retain local typed dialog text
```

### Submit after draft drift

```txt
Finish-review open
  -> capture PendingReviewRevision + keep summary in stable controller
  -> Submit(expectedPendingReviewRevision)
  -> PendingReviewService current GitHub draft read
  -> revision differs => pending_review_changed; no write
  -> UI retains text; explains reopen/review
  -> reopen captures current revision
  -> retry submit
```

### Merge command

```txt
method selection + exact-warning acknowledgement
  -> Merge button
  -> MergeWriteController.merge()
  -> current PR identity + merge readiness read
  -> revision differs => RevisionChanged / Refresh
  -> identity unprovable => Unavailable
  -> warning set differs from acknowledgement => ReadinessChanged
  -> ready => one GitHub merge write
  -> confirmed => Merged + terminal projection
  -> uncertain => OutcomeUnknown + existing recovery flow
```

### Failure / idempotency / cancellation

- Confirmed writes schedule one coalesced read-only observation. Failures/cancellation/`OutcomeUnknown` schedule none.
- Observation reads never retry writes; normal visibility/focus/periodic observation later repairs an unsuccessful post-write read.
- The review lock serializes refresh and observation. A candidate is saved only after the second identity check.
- Merge sends exactly once. `OutcomeUnknown` is recoverable, never automatically retried.
- Safe diagnostics record phase/category only: `observation`, `revision_changed`, `unavailable`, `terminal`, `readiness_changed`, `outcome_unknown`.

## Risks and Open Questions

- Confirm GitHub adapter can provide base SHA and patch identity without broad/unbounded reads. If not, `Unavailable` is required; do not treat head-only as proof.
- Confirm published-feedback evidence is sufficient to classify a removed Finding receipt. Retain it as non-actionable history if ambiguous.
- Find the existing uncertain-merge recovery entrypoint before wiring `OutcomeUnknown`; do not assume pending-review recovery covers it.
- Baseline full browser failures before treating them as unrelated. Run focused read-only Electron checks for theme, keyboard, responsive layout, and error copy.
