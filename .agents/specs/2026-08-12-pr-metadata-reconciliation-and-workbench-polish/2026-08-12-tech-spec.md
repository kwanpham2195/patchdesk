# Same-revision GitHub reconciliation and compact merge command

## Summary

Automatic reconciliation is permitted only after canonical proof that GitHub's current `(head, base, unified diff)` equals the represented revision. It is durable, serialized with all review operations, and recoverable across snapshot/session/review storage. Explicit Refresh remains the only changed-code adoption path. Merge is one explicit compact command with exact warning acknowledgement.

## Context / Current State

Current detection compares a head and metadata fingerprint behind a private refresh lock. `ReviewWriteGate` treats `detectedUpdate` as stale but has no unavailable state. `ReviewWriteCoordinator` serializes writes independently. `ReviewRemoteStore` declares Conversation but its storage parser omits it. Confirmed writes remain in `RecentReviewWrite` normalization until Refresh. Merge uses an unversioned acknowledgement boolean. Startup recovery reconciles merge operations, while the workbench publication-recovery endpoint reloads a projection.

## Goals

- Prove revision equality, or block writes without claiming freshness.
- Persist and recover safe cross-store reconciliation.
- Adopt the authoritative draft only outside locked writes.
- Keep action feedback local, typed, and understandable.
- Keep UI components small: flow owns stable text/scheduling, specialized services own lifecycle, compact merge component owns presentation.

## Non-Goals

- Head-only reconciliation, automatic code/worktree/Insight adoption, remote write retry, new recovery UI, or a tree theme preference.

## Invariants

```ts
type RevisionIdentity = {
  readonly headSha: GitSha;
  readonly baseSha: GitSha;
  readonly patchHash: ContentHash;
};

type RevisionComparison =
  | { readonly _tag: "Same"; readonly identity: RevisionIdentity }
  | { readonly _tag: "Changed"; readonly identity?: RevisionIdentity }
  | { readonly _tag: "Unavailable"; readonly reason: RevisionUnavailableReason };

type ReviewFreshness =
  | { readonly _tag: "Fresh" }
  | { readonly _tag: "RevisionChanged"; readonly detectedAt: IsoTimestamp; readonly identity: RevisionIdentity }
  | { readonly _tag: "Unavailable"; readonly detectedAt: IsoTimestamp; readonly reason: RevisionUnavailableReason };
```

- No `Same` without parsed base SHA, complete diff, and byte-equivalent normalized patch hash.
- `ReviewWriteGate` accepts only `Fresh`; successful `Same` clears `Unavailable`.
- Observation saves candidate snapshot, then session, then Review under one operation journal. A projection is emitted only after journal removal.
- Pending state changes only through `PendingReviewService`, which leaves `WriteInFlight`/`OutcomeUnknown` unchanged.
- Terminal status can apply despite changed identity, but no changed content/metadata/draft is adopted.

## Alternatives Considered

### Refresh for every change

Safe but too disruptive after confirmed actions.

### Background reconciler with independent locks

Races refresh/writes and can project mixed state; rejected.

### Shared coordinator and journal (recommended)

One review-level transaction-like orchestration layer coordinates existing specialized services. It localizes ordering/recovery without pretending local files are an atomic database.

## Proposed Design

### Domain Model and Types

```ts
export type RevisionUnavailableReason =
  | "base_missing"
  | "diff_incomplete"
  | "github_read"
  | "comparison_ambiguous"
  | "reconciliation_incomplete";

export type ReviewObservation =
  | { readonly _tag: "Unchanged"; readonly detectedAt: IsoTimestamp }
  | { readonly _tag: "Reconciled"; readonly projection: ReviewWorkbenchProjection }
  | { readonly _tag: "RevisionChanged"; readonly detectedAt: IsoTimestamp; readonly identity: RevisionIdentity }
  | { readonly _tag: "Unavailable"; readonly detectedAt: IsoTimestamp; readonly reason: RevisionUnavailableReason }
  | { readonly _tag: "Terminal"; readonly status: "merged" | "closed"; readonly detectedAt: IsoTimestamp };

export type ReviewObservationJournal = {
  readonly schemaVersion: 1;
  readonly profileId: WorkspaceProfileId;
  readonly reviewId: ReviewId;
  readonly expectedReviewUpdatedAt: IsoTimestamp;
  readonly expectedSessionUpdatedAt: IsoTimestamp;
  readonly previousSnapshotHash: ContentHash;
  readonly nextSnapshotHash: ContentHash;
  readonly nextPendingReview: PendingReviewState;
  readonly createdAt: IsoTimestamp;
};

export type MergeWarningAcknowledgement = {
  readonly revision: RevisionIdentity;
  readonly warningCodes: ReadonlyArray<MergeWarningCode>;
};
```

### Types, Interfaces, and APIs

```ts
class ReviewOperationCoordinator {
  withReviewLock<T>(
    profileId: WorkspaceProfileId,
    reviewId: ReviewId,
    operation: () => Promise<T>,
  ): Promise<T>;
}

class GitHubRevisionIdentityReader {
  read(input: {
    readonly profile: WorkspaceProfileConfig;
    readonly pr: PullRequestRef;
    readonly represented: RevisionIdentity;
  }): Promise<Result<RevisionComparison, GitHubReadFailure>>;
}

class ReviewObservationService {
  observe(input: { readonly profileId: WorkspaceProfileId; readonly reviewId: ReviewId }): Promise<Result<ReviewObservation, ReviewObservationFailure>>;
  recover(input: { readonly profileId: WorkspaceProfileId; readonly reviewId: ReviewId }): Promise<Result<ReviewObservation, ReviewObservationFailure>>;
}

class PendingReviewService {
  adoptObservedState(input: {
    readonly profileId: WorkspaceProfileId;
    readonly reviewId: ReviewId;
    readonly observed: ViewerPendingReview | undefined;
    readonly publishedFeedback: GitHubPublishedFeedback | undefined;
    readonly evidenceComplete: boolean;
  }): Promise<Result<PendingReviewAdoption, PendingReviewServiceFailure>>;
}
```

`GitHubRevisionIdentityReader` calls `getPullRequest`, requires `baseSha`, calls `getPullRequestDiff({ snapshot: { baseSha, headSha } })`, normalizes with the exported preparation normalizer, and hashes with the shared content-hash function. Compare against the represented session patch hash. It may return `Changed` only with clear different identity; otherwise failed/incomplete comparison returns `Unavailable`.

`Review` schema adds `freshness: ReviewFreshness`; decoder migrates legacy records. `detectedUpdate` is removed only after migration readers and fixtures have been converted.

### Seams, Boundaries, Adapters, and Implementations

- **Coordinator:** replace private refresh lock and `ReviewWriteCoordinator`. Explicit refresh, observation, pending writes, merge, and `ReviewRecoveryService.reconcilePublication` acquire it.
- **Freshness / gate:** `Review` owns persisted state; `ReviewStore` compare-and-save owns conflicts; `ReviewWriteGate.requireFresh` rejects non-`Fresh`.
- **Revision reader:** adapter/application seam; raw GitHub diff never crosses renderer boundary.
- **Observation journal:** storage seam. Candidate snapshot may be orphaned. Journal recovery must complete exact expected versions or save `Unavailable(reconciliation_incomplete)`.
- **Remote snapshot:** upgrade `ReviewRemoteStore.snapshotSchema`, parser, fixtures, and backwards reader to include bounded `Conversation`.
- **Pending review:** creates Historical receipts after complete evidence; incomplete evidence keeps non-actionable history. It supplies opaque `PendingReviewRevision` to the projection and verifies it on Submit.
- **Recent write journal:** belongs to observation normalization only. Consume entries after durable candidate evidence includes their receipts; Refresh clears them after durable complete snapshot.
- **Merge recovery:** extend existing `/v1/reviews/publication/recover` and `ReviewRecoveryService` from publication-only reconciliation to reconcile both known Review-owned merge operations and publication evidence, then load its projection. The existing outcome-unknown recovery surface invokes that route; no new button.

## Call Stacks and Data Flow

### Revision proof

```txt
Review/session patch hash
  -> GitHubRevisionIdentityReader
  -> getPullRequest (head/base)
  -> getPullRequestDiff(snapshot base/head)
  -> shared normalizePatch + SHA-256
  -> Same | Changed | Unavailable
```

### Observation transaction

```txt
visible workbench / confirmed write
  -> ReviewOperationCoordinator.withReviewLock
  -> load Review/session/snapshot @ versions
  -> revision proof #1
  -> metadata + Conversation + pending + published reads
  -> revision proof #2
  -> save content-addressed candidate
  -> save observation journal
  -> PendingReviewService.adoptObservedState
  -> session compare-and-save
  -> Review compare-and-save (new snapshot, Fresh)
  -> remove journal
  -> project
```

Failure after journal creation:

```txt
startup/existing recovery surface
  -> coordinator lock
  -> load journal + current versions
  -> exact next state? remove journal
  -> exact previous state? finish ordered transition
  -> otherwise save Review Freshness.Unavailable(reconciliation_incomplete)
  -> do not project a mixed snapshot/session
```

### Post-write and locked state

```txt
confirmed write -> coalesced observation
failed/outcome unknown -> no immediate observation
ordinary visible observation -> metadata allowed; PendingReviewService returns Locked unchanged
candidate evidence includes RecentReviewWrite -> consume entry
```

### Merge

```txt
selector + revision/warning-bound acknowledgement
  -> coordinator lock
  -> revision proof + current merge policy
  -> Changed | Unavailable | changed warning set => typed no-write result
  -> one GitHub merge write
  -> confirmed terminal projection | durable OutcomeUnknown
  -> existing recovery route reconciles Review-owned merge operation if outcome unknown
```

2. Revision reader proves equal normalized diffs and rejects missing/incomplete/ambiguous inputs; base/head/patch changes are distinct.
3. Coordinator serializes refresh/write/observation/recovery; journal step failures never project mixed state and recover deterministically.
4. Remote snapshot Conversation round-trip; confirmed-write normalization entries consume only after evidence appears.
5. Draft adoption preserves locked states; receipt ambiguity stays non-actionable; Finish review retains text and blocks drifted submit with zero write.

7. Pierre light/dark and compact merge keyboard/narrow-layout browser/renderer tests.

## Risks and Open Questions

- Verify the preparation patch normalizer can be safely exported and GitHub returns byte-equivalent full diffs; otherwise stop.
- Verify the existing recovery surface can represent a merge outcome unknown without a new button; otherwise stop.
- Published-feedback completeness may prevent reactivating old Findings; retain them historical/non-actionable.
- Baseline browser failures before treating them as unrelated.
