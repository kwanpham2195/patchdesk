# 03 — Review workbench scenarios

**What to build:** A designer can open stable prepared, running, and completed review scenarios and inspect the workbench's diff, checks, findings, comments, review-draft, submission, merge-readiness, and confirmation surfaces with local mock actions.

**Blocked by:** 01 — Design app foundation and default inbox

**Status:** ready-for-agent

- [ ] Prepared, running, and completed workbench scenarios are directly addressable.
- [ ] Diff, checks, overview, progress, findings, comments, and merge-readiness surfaces render realistic content.
- [ ] Model selection, reasoning selection, run-start, progress, reconnect, and completion states use deterministic mock responses.
- [ ] Review submission and merge confirmation surfaces are available as indexed scenarios or reachable local interactions.
- [ ] Draft comment, submission, and merge interactions never call GitHub or persist real review state.
- [ ] Workbench scenarios preserve the current shell, density, theme, and responsive behavior.
