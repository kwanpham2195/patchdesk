# Domain docs

Before exploring or naming a Patchdesk domain concept, read [the product glossary](../product-description/glossary.md). Use its terms and words-to-avoid guidance in issues, proposals, tests, and code comments. When glossary edits are authorized, add missing current terms there after checking the product description and source. During read-only work, propose the glossary change in the report.

Read the [ADRs](../adr/) that govern the area. If a proposal conflicts with an ADR, name the conflict and the decision that needs revisiting.

The glossary is this repository's vocabulary owner. Do not create a root `CONTEXT.md` or `CONTEXT-MAP.md` for Patchdesk vocabulary.
