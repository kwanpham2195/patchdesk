# Explain Forbidden GitHub Reads

A forbidden `gh` read is now attributed to one of a small closed set of reasons — `ip_allow_list`, `saml`, `insufficient_scopes`, `unknown` — instead of collapsing into the same generic "unavailable" bucket as a transient network blip, which previously told a maintainer blocked by an organization's IP allow list to "retry the read" when retrying could never succeed. The reason crosses the process boundary as a member of that closed enum, never as GitHub's raw message text, preserving the existing design property that `GitHubReadFailure` never leaks `stdout`/`stderr` to the renderer: the renderer receives `ip_allow_list`/`saml`/`insufficient_scopes`/`unknown` and nothing else. `saml` and `insufficient_scopes` are attributed from GitHub's own structured GraphQL signals (`extensions.saml_failure` and `errors[].type === "INSUFFICIENT_SCOPES"`), not message wording, so they are immune to prose drift; `ip_allow_list` is the one reason attributed by matching a specific phrase in GitHub's prose, because GitHub does not expose IP-allow-list as a distinct structured `errors[].type`, and that pattern is pinned to a fixture under `tests/fixtures/gh-command-failures/` per the discipline established for command-failure classification generally, so a wording change fails a test instead of silently reverting to `unknown`. The Maintainer Inbox stops offering a retry button and stops calling the condition temporary for any forbidden reason, including the unattributed `unknown` case, because none of them resolve by asking again and a working retry button would falsely imply one might. Deliberately deferred: a forbidden-reason category on the GitHub write path (`GitHubWriteFailure`/`writeFailure()` still fold a forbidden write into the generic `unavailable` category), `dashboard-service.ts`'s `mapFailure()` and the other `GitHubReadFailure` consumers outside the Maintainer Inbox (`review-diff-source-service.ts`, `review-workbench-controller.ts`, `review-refresh-service.ts`, `review-observation-service.ts`, `published-feedback-service.ts`, `github-revision-identity-reader.ts`, `inline-conversation-service.ts`, `local-api.ts`), which still collapse a forbidden read the same as any other read failure, and REST-sourced `saml`/`insufficient_scopes` attribution, for which no structured signal or fixture evidence exists yet.
