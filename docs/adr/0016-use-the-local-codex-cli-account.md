# Use the local Codex CLI account

Patchdesk supports a **Codex CLI account provider** alongside Pi for Analysis runs and Walkthroughs; the maintainer selects the provider, model, and reasoning level in each run dialog, which repeats the choice before confirmation, preserves separate non-secret preferences per insight type, and records frozen resolved provider/model provenance for the run. Codex is discovered only through inherited PATH and starts only after an explicit user action; each run uses a fresh app-server process and thread against Patchdesk's isolated represented-review worktree (never the maintainer's original checkout), revalidates its live `model/list` choice, and never resumes a thread or starts or embeds login. Patchdesk accepts ordinary command requests whose working directory resolves inside that worktree and relies on Codex's read-only sandbox to prevent mutation; network, stdin-write, file-change, permission, and outside-worktree requests remain declined. Codex results must satisfy the existing strict contracts and authority boundaries, may run concurrently under the ADR "Run Insight types independently", and require deterministic fake-app-server coverage; live-account verification is optional and user-initiated.

> **Note, 2026-09-17 (#240).** Codex threads start with `approvalPolicy: "untrusted"`. Under the earlier default (`on-request` with the read-only sandbox), Codex ran any command it did not flag as dangerous without asking, so Patchdesk's check never ran and the sandbox allowed reads anywhere on the filesystem. Now every command reaches `item/commandExecution/requestApproval`, and `isReadOnlyCommand` (`src/adapters/codex/codex-command-allowlist.ts`) is the gate: it accepts only listed executables and flags, only paths inside the represented worktree, and a `/bin/zsh -lc` script only when it is literal words joined by `&&`. Relative paths resolve against the request's working directory, and every symlink on the resolved path must stay inside the worktree. Stdin writes and network approvals are declined, and a permissions request gets an empty profile, which grants nothing. The one path around the gate is an exec-policy `Allow` rule in the maintainer's global `$CODEX_HOME/rules/default.rules`: Codex runs a matching command without asking, outside the sandbox when every part of it matches. Patchdesk cannot read that file through the protocol, and a rule the maintainer wrote in the Codex TUI is the maintainer's choice. A second residual sits in git: an accepted `git diff`, `git log -p`, or `git show` runs a textconv or external diff driver that the maintainer's own git configuration assigns to a file in the pull request, because Patchdesk does not force `--no-textconv --no-ext-diff`.

> **Superseded, 2026-09-20.** Commit `2e2fac4c` removed the executable and argument allowlist described in the 2026-09-17 note after it declined valid inspection commands and caused Insight runs to return unusable results. Patchdesk now accepts every ordinary command request whose working directory resolves inside the represented worktree. Codex's read-only sandbox remains the mutation boundary. Patchdesk still declines network, stdin-write, file-change, permission, and outside-worktree requests.
