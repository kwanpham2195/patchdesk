# Use the local Codex CLI account

Patchdesk supports a **Codex CLI account provider** alongside Pi for Analysis runs and Walkthroughs; the maintainer selects the provider, model, and reasoning level in each run dialog, which repeats the choice before confirmation, preserves separate non-secret preferences per insight type, and records frozen resolved provider/model provenance for the run. Codex is discovered only through inherited PATH and starts only after an explicit user action; each run uses a fresh app-server process and thread against Patchdesk's immutable represented-review worktree (never the maintainer's original checkout), revalidates its live `model/list` choice, never resumes a thread or starts/embeds login, and may use only verified sandboxed read-only inspection tools scoped to that worktree while Patchdesk denies writes, file changes, network/permission escalation, and every request whose scope cannot be verified. Codex results must satisfy the existing strict contracts and authority boundaries, may run concurrently under the ADR "Run Insight types independently", and require deterministic fake-app-server coverage; live-account verification is optional and user-initiated.

> **Note, 2026-09-17 (#240).** Codex threads start with `approvalPolicy: "untrusted"`. Under the earlier default (`on-request` with the read-only sandbox), Codex ran any command it did not flag as dangerous without asking, so Patchdesk's check never ran and the sandbox allowed reads anywhere on the filesystem. Now every command reaches `item/commandExecution/requestApproval`, and `isReadOnlyCommand` (`src/adapters/codex/codex-command-allowlist.ts`) is the gate: it accepts only listed executables and flags, only paths inside the represented worktree, and a `/bin/zsh -lc` script only when it is literal words joined by `&&`. Stdin writes and network approvals are declined, and a permissions request gets an empty profile, which grants nothing. The one path around the gate is an exec-policy `Allow` rule in the maintainer's global `$CODEX_HOME/rules/default.rules`: Codex runs a matching command without asking, outside the sandbox when every part of it matches. Patchdesk cannot read that file through the protocol, and a rule the maintainer wrote in the Codex TUI is the maintainer's choice.
