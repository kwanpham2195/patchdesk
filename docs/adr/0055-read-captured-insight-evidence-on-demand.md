Supersedes the input, inspection-count, and native permission boundaries in ADRs [0016](0016-use-the-local-codex-cli-account.md), [0041](0041-drive-pi-directly-without-flue.md), and [0054](0054-use-the-local-pi-cli-account.md). Their lifecycle and result authority remain. Brief keeps the structure and citation rules in ADRs 0036 and 0040.

A large represented patch previously entered the first model request. Brief, Walkthrough, Analysis, and Guide now start with captured revision identity and an evidence entry. The parent captures each run under the Review lock and retains the complete expected file set and digests. A writable manifest, current HEAD, or a fresh pull request lookup cannot replace that authority.

The API runtime exposes `read_evidence_page` and `search_evidence`. Native account providers read the same captured NDJSON files through their inspection tools. A fragment preserves the original source byte offsets, file and hunk identity, and source line coordinates. A page's physical line number is never a citation. The initial text request is at most 32,768 UTF-8 bytes, with tool and output schemas measured separately. Each encoded API text-content response is at most 16,384 bytes, with at most 256 physical page lines and 2,048 bytes per serialized record. These are transport bounds, not a new total-patch limit.

The parent validates the complete required set before invocation, after invocation, and before retaining output. Missing or changed evidence fails explicitly and preserves a prior result. API inspection has no application call-count or model-turn ceiling. Existing run timeouts, cancellation, output bounds, snapshot bounds, and three transient retries remain. Submission does not require a count of pages read.

Analysis can report a typed incomplete outcome. It produces no new verdict and preserves the prior revision-labelled result. Low confidence alone does not make a complete result incomplete. Successful Brief aliases and deterministic counts, Walkthrough citations and uncited counts, Guide membership and Others, and Analysis verdict and location validation remain parent-owned.

Codex requests native `on-request` approval with `auto_review` and a workspace-write sandbox. Patchdesk verifies the effective policy and empty instruction sources before a generating turn, and rejects unsupported or refused settings. It does not replace native review with unconditional approval. Runs use an owned private home, disable inherited skills, MCP, apps, hooks, and plugins, and compare managed requirements, account identity, and selected provider settings before the turn. A nullable default provider is resolved only for the observed Codex 0.162.1 contract; an unknown version with no explicit provider fails closed. The supported file-backed login supplies an access token without its refresh token. Patchdesk checks the source login and configuration for changes and never refreshes or rewrites them. An unsupported store or insufficient token lifetime fails clearly.

Pi account runs enable `read`, `grep`, `find`, `ls`, and `bash`, while excluding `edit` and `write`. Bash is not an enforced read-only shell. Extensions, MCP, skills, prompt templates, themes, and context files are disabled, and offline mode prevents automatic resource discovery. Model and thinking selection are checked before the prompt. These tools grant neither result authority nor permission to publish.

Native process cessation precedes private-home removal. Uncertain cessation preserves the home and reports cleanup failure. An initial directory identity failure can leave an empty directory before credential creation. Removal is not a secure-erasure guarantee. Diagnostics retain only bounded allowlisted phase, code, and safe detail, with another sanitization at the parent boundary.

The managed-refusal runtime probe remains unverified; its prerequisite was waived by the maintainer. Pi 1.2.0 was exercised. The retained minimum version 0.80.4 has not been exercised with the new isolation flags. Fake-provider captures prove application wiring, not native permissions or model quality. One earlier-format Codex PR Walkthrough completed with verified retained citations and observed owned process/home cleanup. An earlier cleanup failure remains unexplained; that success does not establish its cause or complete the provider matrix.

## Walkthrough production and retained reading

Walkthrough uses ordered durable operations instead of submitting a complete JSON result. This changes the Walkthrough submission and retry rules above, the account-provider availability in ADRs 0016 and 0054, the submission rules in ADR 0041, the path-in-prose rule in ADR 0036, and invalid-result recovery in ADR 0019. Their other decisions remain unchanged.

### Decision

The API-key producer has six tools: `begin_walkthrough`, `open_chapter`, `open_section`, `add_citations`, `finish`, and `lookup_receipt`. Begin occurs once, first. Patchdesk assigns chapter and section IDs in reading order. Only the latest chapter accepts sections, and only the latest section accepts citations. Each section needs a citation before another section or chapter opens; each chapter needs a section. Duplicate or unknown hunk IDs refuse the whole batch. One hunk can belong to only one section. Paths and coordinates come from captured evidence, not path strings repeated in prose. These checks establish citation identity, not the truth of the explanation.

Each accepted mutation commits an identity-bound operation and receipt with the runtime's receipt index in the run journal. Identical `opId` replay returns its receipt; conflicting reuse is refused. Lookup does not mutate state. Finish freezes the receipt sequence and closes new mutations and paid requests. The child's final acknowledgment cannot publish a result. Every provider request needs an exact stored body and durable dispatch intent before permission; uncertain requests pause the run without automatic retry. The generic three-transient-retry rule does not apply to this producer.

`WalkthroughPreparedInput1` retains the captured patch, inventory, context, evidence manifest, and exact hunk index. Text uses blocked TextRoots; physical objects stay within 16 KiB. A worker revalidates the complete captured evidence and every hunk, including uncited hunks, before publication. It independently replays frozen receipts, derives order, chapter spans and unique citations, builds the full ordered uncited complement, and reads back the stored graph. Publication compares the represented session, base, head and patch, Binding, preparation, generation, cancel epoch, frozen receipts, validation descriptors, and slot version and digest under the existing Review/slot/journal lock order. Only then does the pointer name `WalkthroughResultRoot1` and `WalkthroughPublication1`. A committed pointer stays successful if later journal bookkeeping fails.

The result root references chapter, section, citation, hunk and uncited indexes rather than embedding complete arrays. `WalkthroughReadingState1` stores reviewed section IDs and the current section behind a separate per-result-digest progress pointer. Single-section mutations check the digest and expected version, validate section existence, and recheck the result and open Review under the publication Review lock before compare-and-replace. Missing progress is empty; malformed explicit state is an error, not an empty replacement. A new result starts with no marks. Old-format results and progress remain stored but are not imported or shown through a prose fallback.

UI, local API and MCP reads share bounded summary, navigation, section, citation, uncited and continued hunk-text services. Navigation and citation pages contain at most ten items and also obey the byte budget. Encoded replies, including MCP text-content and structured-content envelopes, fit 32 KiB. Producer arguments, channel frames and encoded tool replies have their own 32 KiB bounds; captured evidence replies keep the separate 16 KiB bound. Cursors bind the exact result digest, page kind, scope and position. A stale digest is refused, not remapped. A malformed current result is an explicit error. Reading, reopening and status checks never invoke a provider.

The shared UI read pool admits four active reads and at most 64 FIFO waiters. Further waiters are refused. Aborting an obsolete read removes its waiter; a started worker read retains its lease until completion. Authority and per-run quotas remain separate. The renderer holds one active section and bounded navigation and citation windows, and assembles only requested hunk text with its original line numbers.

`walkthrough-deadline/1` preserves the size-scaled 5 to 20 minute generation budget. Begin records immutable `startedAt` and `deadlineAt` using captured patch/context bytes and a sizing hunk count capped at 113. It stages a linked Authorization without rewriting the original authorization time. Host request admission and the runtime abort timer enforce the deadline. Explicit Resume requires acknowledgment of unknown spend, starts a new generation, and preserves the exact original deadline and dispatch history. Expired runs cannot dispatch. Guide retains `no-total-deadline/1`.

### Consequences and limits

Walkthrough generation currently accepts API keys only. Codex CLI account and pi CLI account requests are refused until the #821 provider-parity follow-up; there is no whole-result fallback. A valid previous result stays readable during replacement, failure, cancellation and pause. Earlier-format results show unavailable with Regenerate, without rewriting their bytes or progress.

The old aggregate chapter, section and citation caps and the 2 MiB prompt-patch refusal no longer govern this path. The 64 MiB captured-patch ceiling, concise text-field limits, hunk-parser limits, finite indexes, provider context limits and durable generation deadline remain. Preparation still materializes content-sized patch, context, inventory, evidence and hunk data; receipt maps and transcripts also grow. Bounded messages do not prove content-independent allocation.

The isolated 952-hunk retention test took about 42 seconds after batching durable indexes. That is an end-to-end test cost, not capture time alone; instrumented hunk capture took about 18 seconds. It is not a real-provider benchmark. The #821 continuation/performance follow-up still owns content-independent allocation and pinned W1 acceptance, with 1,047 files and 1,714,276 patch bytes. The PR #140 live check is not W1. Account-provider parity and Local/MCP live acceptance remain pending.
