# Separate PR reconciliation from revision refresh and merge confirmation

Patchdesk keeps an open Review pinned to a represented revision. A background read may reconcile GitHub state only after it proves that the open pull request still has the represented revision identity: head SHA, base SHA, and patch identity. If it cannot prove that identity, Patchdesk keeps the last known read-only state, blocks GitHub writes as unavailable, and waits for a successful check. If the identity changed, it exposes **Refresh**; only explicit Refresh adopts the revision, prepares its worktree, and replaces revision-bound artifacts. This supersedes ADR-0001 for same-revision GitHub state.

A same-revision reconciliation may quietly adopt bounded PR metadata, Conversation, merge readiness, and the authenticated viewer's authoritative pending review. It never merges local and remote drafts. Pending-review lifecycle rules remain in `PendingReviewService`: a remote draft replaces the confirmed local draft only when no operation is in flight or outcome is unknown. Old Finding receipts remain historical; a Finding becomes actionable again only when GitHub evidence proves it is neither in a pending draft nor published. Terminal remote state is the narrow exception: if GitHub says the pull request is merged or closed, Patchdesk marks the Review terminal and stops writes without adopting any changed revision or its metadata.

Merge uses a selected method and one explicit **Merge** command, not a confirmation dialog. Before the write, Patchdesk rechecks current revision identity and readiness. Each acknowledged warning token binds to the represented revision and the exact warning-code set; a changed set invalidates it. The merge command returns distinct readiness-changed, revision-changed, unavailable, outcome-unknown, and merged outcomes. Refresh is only for a changed revision; an uncertain merge uses the existing recovery flow and is never retried automatically.
