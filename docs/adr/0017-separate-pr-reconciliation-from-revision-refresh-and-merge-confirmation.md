# Separate PR reconciliation from revision refresh and merge confirmation

Patchdesk keeps an open Review pinned to a represented revision. A background read may reconcile GitHub state only after it proves the open pull request still has the represented revision identity: head SHA, base SHA, and the canonical hash of GitHub's complete unified diff. The comparison hash uses the same normalized bytes and hash function as the represented session patch. Missing base SHA, an incomplete diff, a failed diff read, or a hash mismatch that cannot be classified as changed is **unavailable**. Patchdesk keeps the last known read-only state and blocks GitHub writes until a later successful same-revision check. A verified identity change exposes **Refresh**; only explicit Refresh adopts the revision, prepares its worktree, and replaces revision-bound artifacts. This supersedes ADR-0001 for same-revision GitHub state.

A same-revision reconciliation may quietly adopt bounded PR metadata, Conversation, merge readiness, and the authenticated viewer's authoritative pending review. It never merges local and remote drafts. Pending-review lifecycle rules remain in `PendingReviewService`: a remote draft replaces confirmed local state only when neither an operation is in flight nor its outcome is unknown. Old Finding receipts remain historical; a Finding becomes actionable again only when GitHub evidence proves it is neither in a pending draft nor published. Terminal remote state is the narrow exception: if GitHub says the pull request is merged or closed, Patchdesk marks the Review terminal and stops writes without adopting changed revision content or metadata.

One shared review-operation coordinator serializes Refresh, observation, all GitHub writes, and recovery for a profile/review pair. Reconciliation uses a durable observation journal: it writes the candidate snapshot first, then records its intended session/review transition. Until the transition is completed or recovered, the workbench is unavailable and no mixed snapshot/session projection is exposed.

Merge uses a selected method and one explicit **Merge** command, not a confirmation dialog. Before the write, Patchdesk rechecks current revision identity and readiness. Each acknowledgement binds to the represented revision and exact warning-code set; a changed set invalidates it. The merge command returns distinct readiness-changed, revision-changed, unavailable, outcome-unknown, and merged outcomes. Refresh is only for a changed revision. An uncertain merge is never retried automatically. The existing workbench recovery action extends its route to reconcile the durable merge operation as well as publication evidence, then reloads the Review; it adds no new control.
