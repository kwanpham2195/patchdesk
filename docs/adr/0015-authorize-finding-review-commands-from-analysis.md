# Authorize Finding review commands from Analysis

Analysis presents a current Mapped Finding and its exact containing represented-patch hunk, expanded by default, in the Analysis screen. It highlights the Finding's verified range without routing to Files or generating a snippet. A maintainer's explicit **Add to review** action immediately uses that Finding's suggested text, or its explanation when no suggestion exists, to start the viewer's GitHub pending review or append to it; it does not open an editor, retain a local queue, generate new text, or run automatically when Analysis completes. A confirmed GitHub failure leaves the Finding actionable; only an uncertain outcome locks further Finding commands until explicit GitHub reconciliation. A successful command persists an immutable Finding review receipt linking the Analysis Finding to the resulting GitHub thread. The receipt visibly identifies the Finding as in the viewer's Pending review or Published. A confirmed submit marks that receipt published immediately, while a confirmed discard removes it; neither requires a separate waiting-for-refresh state. A published receipt makes its Finding unavailable for the rest of that Analysis run and represented revision, preventing duplicate GitHub comments; a refreshed revision or regenerated Analysis creates new identities that may be actionable. A confirmed discard removes the receipt and makes its Finding actionable again. The Analysis-summary action appears only when the current pending review contains at least one current Finding review receipt. It opens the shared Finish review interface with editable high-level scope, change, verification, and verdict context, and does not preselect the GitHub outcome; it never creates an empty review or publishes unselected Finding detail. After Refresh moves to a new revision, the old Analysis remains readable but contributes no hunk, Finding, or summary action. This extends ADR-0014's single pending-review owner while preserving one deliberate maintainer authorization per GitHub write.
